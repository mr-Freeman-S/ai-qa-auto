# Локальный регресс: Ollama + Claude Code + Google Chrome

Одинаковая папка для двух Mac (macOS 14+, Apple Silicon). Python и agent.py не нужны.
Модель по умолчанию — qwen3.5:4b, контекст 64K. Это пилот: результаты модели проверяет человек.

## Первый запуск одной командой

Откройте Terminal в этой папке и выполните:

```bash
bash start.sh
```

Скрипт скачает локальный Node.js 22, если подходящего Node нет, установит зависимости из package-lock.json,
недостающие Chrome/Ollama в /Applications и Claude Code официальным установщиком,
запустит Ollama, скачает модель и создаст qa-local. Затем запустит DISP-01 и DISP-02 для сисадмина.
Существующие приложения не переустанавливаются. Интернет нужен для установки и staging.
macOS может запросить разрешение открыть приложения; при отсутствии прав на /Applications установите их вручную.
При первом запуске Ollama завершите её приветственный экран; если скрипт завершился раньше — повторите команду.
В Claude Code подтвердите доверие к папке и использование MCP. В Chrome войдите вручную и напишите агенту «Вошёл, продолжай».
Это интерактивный запуск: инструменты Playwright заранее разрешены в .claude/settings.json; остальные разрешения Claude Code остаются стандартными. Авторизация не автоматизирована.
Запуск без аргументов предполагает тестовый аккаунт сисадмина. Для другой роли укажите её явно.

## Выбор порции или кейса

```bash
bash start.sh smoke --role sysadmin
bash start.sh DISP-01 --role member
bash start.sh 03-grid-01 --role sysadmin --table "Пользователи"
bash start.sh login --role teamadmin
```

Роли: sysadmin, senior, teamadmin, member. Для выбранной роли обязательна заполненная пара в .env.
Chrome запускается с --isolated; старые profiles/ не используются и не удаляются.

Быстрый запуск после установки (без повторной подготовки):

```bash
bash run.sh list
bash run.sh run 01-disp-01 --role sysadmin
bash run.sh run USR-06 --role sysadmin
bash run.sh run DISP-01 --role member --dry-run
```

`--dry-run` печатает задание, не запускает Chrome/Claude и не создаёт отчёт.
Список всех 47 порций: [batches/INDEX.md](batches/INDEX.md).
Каждая порция содержит до трёх кейсов одного раздела. 123 исходных ID сохранены без изменения текста.
Один ID может содержать много условий: роли, типы полей и таблицы проверяются отдельно.
GRID обязательно требует --table; это не означает прохождение того же кейса для остальных таблиц.
Новый запуск создаёт новую историю модели и чистую сессию Chrome. Каждая slash-команда начинает с browser_close и нового входа из .env; между кейсами одной команды сессия сохраняется.

## Данные для проверок с изменениями

Скопируйте fixtures.example.md в fixtures.local.md и укажите реальные тестовые сущности,
состояния, допустимые операции и ожидаемые числа. Затем:

```bash
bash run.sh run TEAM-02 --role sysadmin --fixtures fixtures.local.md
```

Без подготовленных данных зависимые проверки должны получить BLOCKED. Связанные кейсы требуют
предусловий от предыдущих шагов; скрипт не создаёт и не сбрасывает стенд автоматически.
Режим «Посмотреть как» не заменяет проверку прав отдельного пользователя.
FRM-03 и FLC-06 расходятся в условиях удаления — нужно уточнить требование.
ANS-05 требует доказательств из приёмника webhook. Визуальные/временные проверки не доказываются одним DOM-снимком.

## Отчёты и настройки

Каждый прогон создаёт reports/<время>-<порция>-<роль>/ с prompt.txt, run.json и results.md.
Агент дополняет results.md и сохраняет доказательства. run.json фиксирует запуск, а не результат тестов.
Если агент завершился без отчёта, начальный NOT_RUN остаётся — это не PASS.
Статусы: PASS, FAIL, BLOCKED, AGENT_ERROR. Не проверенные условия перечисляются отдельно.

Общие параметры в config.json: URL, baseModel, model, context, batchSize, chromePath.
Чтобы изменить модель на обоих Mac, измените config.json и повторите bash start.sh.
Modelfile генерируется из config.json. Модели Ollama хранятся отдельно от этой папки.
MCP закреплён на версии 0.0.85, транзитивные зависимости — в package-lock.json.
Claude Code и приложения устанавливаются в актуальных версиях, их версии на разных Mac могут отличаться.
Модель подключена к localhost:11434, облачная модель не настроена.

После правок исходного regression.md:

```bash
bash run.sh split
```

Передайте боссу папку с исходниками, включая скрытые .mcp.json и .gitignore,
но без node_modules/, .runtime/, profiles/, chrome-profile/, reports/ и fixtures.local.md.
Внутри нет абсолютных путей к домашнему каталогу автора.
Остановить работу: Ctrl+C. Полный регресс здесь ещё не запускался.

## Команды внутри Claude Code

После установки запустите чат:

```bash
bash run.sh chat --role sysadmin
```

Внутри Claude Code:

```text
/regress_1
/regress_3 таблица Пользователи
/regress_all
```

Доступны /regress_1 … /regress_47 по порядку batches/INDEX.md.
/regress_all проходит все порции для текущей роли (не все четыре роли), GRID — для доступных таблиц.
Без тестовых данных зависимые проверки будут BLOCKED. Команды не запускают вложенный Claude Code.
При переполнении контекста модель сохраняет точку продолжения в results.md; её можно передать
в новом чате: `/regress_all продолжить с порции N, предыдущий отчёт reports/.../results.md`.
Один длинный прогон на 4B-модели не гарантирует завершения без вмешательства.

Файлы команд находятся в .claude/commands/, общие инструкции — .claude/regress-workflow.md.
Они передаются боссу вместе с папкой, включая скрытую .claude/.
После изменения настроек перезапустите чат. Однократное доверие к проекту/MCP может остаться;
корпоративные запреты имеют приоритет над локальными разрешениями. Правило mcp__playwright__*
разрешает все инструменты именно этого сервера, включая действия, меняющие данные сайта.
Запись отчётов файловыми инструментами Claude может запросить отдельное подтверждение.

## Автоматический вход через .env

Откройте локальный .env (создаётся при setup) и заполните нужную роль:

```dotenv
QA_SYSADMIN_LOGIN='test-admin'
QA_SYSADMIN_PASSWORD='ваш пароль'
```

Для других ролей: QA_SENIOR_LOGIN/PASSWORD, QA_TEAMADMIN_LOGIN/PASSWORD,
QA_MEMBER_LOGIN/PASSWORD. Шаблон всех имён находится в .env.example.
Затем перезапустите `bash run.sh chat --role sysadmin` и вызовите /regress_1.
В уже открытом чате настройки входа не обновляются.

Каждый запуск и каждый вызов /regress_N или /regress_all начинают с чистого контекста и нового входа. Модель получает только имена
секретов; Playwright MCP подставляет значения из .env при browser_fill_form/browser_type.
Значения не включаются в prompt.txt или аргументы запуска. Файл .env исключён из Git и
запрещён для Read в Claude Code; не добавляйте его в fixtures или отчёты и не передавайте боссу.
Это не абсолютная изоляция секретов от браузерного агента: у него есть доступ к браузеру и другим инструментам.
Автологин разрешён только на origin из config.json; для SSO, MFA, CAPTCHA или ошибки пароля нужен ручной вход.
После одной ошибки агент должен остановиться, чтобы не повторять неверные попытки.
Без заполненной пары секретов launcher останавливается до запуска браузера. Команда login выполняет только новый вход из .env.
При закрытии изолированного браузера cookies и локальное состояние этого контекста теряются. Старые сессии на сервере не отзываются; личный Chrome не затрагивается.
Каждый пользователь заполняет собственный .env. Боссу передаётся только .env.example.

## Что передавать по итогам

Один файл `reports/<папка-прогона>/results.md`: сводка, таблица статусов, описания ошибок
и список непроверенного. В пределах чата все /regress_N дополняют один results.md.
Служебные файлы рядом нужны для диагностики, передавать их вместе с результатами необязательно.
Новый чат создаёт новый файл; автоматического объединения результатов разных чатов нет.
