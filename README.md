# Локальный регресс: Ollama + Claude Code + Google Chrome

Одинаковая папка для двух Mac (macOS 14+, Apple Silicon). Python и agent.py не нужны.
Модель по умолчанию — qwen3.5:4b, контекст 64K. Это пилот: результаты модели проверяет человек.

## Обычный запуск и результат в Markdown

Запуск снова интерактивный: Claude Code управляет браузером в текущем чате и
после каждого кейса записывает результат прямо в `reports/<папка-прогона>/results.md`,
затем перечитывает его для проверки сохранения. Текст в чате не заменяет файл отчёта.
Режимы `batch`, `resume`, `--auto` и ограничитель браузерных вызовов удалены.
Существующие отчёты сохранены. Удаление дублирующихся проверок между ролями действует.

Для локальной модели Ollama + Playwright:

```bash
bash run.sh chat
```

В открывшемся Claude Code введите команду роли, при необходимости с разделом:

```text
/regress_sysadmin DISP
/regress_sysadmin TEAM
```

Для всего набора роли — `/regress_sysadmin`. Затем аналогично проверяйте senior,
teamadmin и member. Лучше открывать новый чат на каждую роль, чтобы история не
росла на весь регресс сразу. Для входа через Playwright нужны секреты ролей в `.env`.

Для облачного Claude с расширением Claude in Chrome:

```bash
bash run.sh cloud
```

Внутри Claude Code:

```text
/regress-chrome sysadmin DISP
```

Для всего набора — `/regress-chrome sysadmin`. В Chrome входите вручную под нужной
ролью, как описано ниже. Корневая папка отчёта печатается при запуске; команды одного
чата дополняют один `results.md`. Новые чаты получают отдельные папки отчётов.

Проверка одного кейса без предварительного чата (локальная модель):

```bash
bash run.sh run DISP-02 --role sysadmin
```

В результате `results.md` содержит статусы кейсов, фактические наблюдения, ошибки,
непроверенные условия и созданные/изменённые сущности. PASS допустим только для
проверенных условий. Отчёты прошлых запусков не удаляются и автоматически не объединяются.

## Первый запуск одной командой

Откройте Terminal в этой папке и выполните:

```bash
bash start.sh
```

Скрипт скачает локальный Node.js 22, если подходящего Node нет, установит зависимости из package-lock.json,
недостающие Chrome/Ollama в /Applications и Claude Code официальным установщиком,
запустит Ollama, скачает модель и создаст qa-local. Затем запустит DISP-01 и DISP-02 для сисадмина.
Существующие приложения не переустанавливаются. Интернет нужен для установки и staging.
macOS может запросить разрешение открыть приложения; при отсутствии прав на /Applications установите их вручную.
При первом запуске Ollama завершите её приветственный экран; если скрипт завершился раньше — повторите команду.
В Claude Code подтвердите доверие к папке и использование MCP. Для обычного входа
заполните секреты роли в .env; при MFA/SSO/CAPTCHA завершите вход вручную.
Это интерактивный запуск: инструменты Playwright заранее разрешены в .claude/settings.json; остальные разрешения Claude Code остаются стандартными.
`start.sh` после подготовки запускает `run`. Чтобы только установить окружение,
выполните `bash run.sh setup`, затем откройте чат командой `bash run.sh chat`.
Запуск без аргументов предполагает тестовый аккаунт сисадмина. Для другой роли укажите её явно.

## Наборы по ролям

Кейсы распределены по ролям в [roles.json](roles.json) и сгруппированы по разделам в
[suites/](suites/INDEX.md): `suites/sysadmin.md`, `senior.md`, `teamadmin.md`, `member.md`.
GRID-кейсы разворачиваются в отдельные строки «GRID-NN × Таблица» по таблицам, доступным роли.
Общие проверки из `roles.json → sharedChecks` закреплены за сисадмином и автоматически
исключены из наборов остальных ролей. Сейчас это темы/лоадеры, GRID-02…10,
USR-03, TEAM-03, FRM-02, FRM-04, FBUILD-03 и PP-05. Проверки доступа,
видимости и ролевых действий сохранены. GRID-01 (изоляция настроек пользователя)
и GRID-11 (обновление данных после действий) также оставлены для каждой роли.
Полный регресс = набор сисадмина плюс ролевые наборы; отдельный запуск тимадмина
не покрывает общую механику. Исключённым дублям не присваивается PASS другой роли.
При необходимости прямой запуск конкретного ID через `run` по-прежнему разрешён
с предупреждением, даже если ID исключён из набора роли.

Для разделов, недоступных роли (Каналы, Поля, Настройки), в набор входит проверка отсутствия доступа.
Изменили распределение — правьте roles.json и запускайте `bash run.sh split`
(split проверяет, что каждый кейс попал хотя бы в одну роль).

```bash
bash start.sh smoke --role sysadmin
bash start.sh DISP-01 --role member
bash start.sh TEAM --role teamadmin          # весь раздел из набора роли
bash start.sh GRID-01 --role sysadmin --table "Пользователи"
bash start.sh login --role teamadmin
```

Роли: sysadmin, senior, teamadmin, member. Для выбранной роли обязательна заполненная пара в .env.
Chrome запускается с --isolated; старые profiles/ не используются и не удаляются.

Быстрый запуск после установки (без повторной подготовки):

```bash
bash run.sh list --role senior
bash run.sh run USR --role senior
bash run.sh run USR-06 --role sysadmin
bash run.sh run DISP-01 --role member --dry-run
```

`--dry-run` печатает задание, не запускает Chrome/Claude и не создаёт отчёт.
Сводка наборов: [suites/INDEX.md](suites/INDEX.md). 123 исходных ID сохранены без изменения текста (cases/).
Один ID может содержать много условий: роли, типы полей и таблицы проверяются отдельно.
GRID обязательно требует --table; это не означает прохождение того же кейса для остальных таблиц.
Новый запуск создаёт новую историю модели и чистую сессию Chrome. Каждая slash-команда начинает с browser_close и нового входа из .env; между кейсами одной команды сессия сохраняется.

## Данные для проверок с изменениями

Скопируйте fixtures.example.md в fixtures.local.md и укажите реальные тестовые сущности,
состояния, допустимые операции и ожидаемые числа. Затем:

```bash
bash run.sh run TEAM-02 --role sysadmin --fixtures fixtures.local.md
```

Тесты сами создают нужные сущности с префиксом `QA-AUTO <ММДД-ЧЧММ>` (email — `@example.invalid`)
и меняют только их и то, что явно указано в fixtures.local.md; чужие данные стенда не трогают.
Предусловия, недоступные роли (группы, публикация форм, ПО, ссылки исполнителям), агент готовит шагом
SETUP под сисадмином и затем проверяет под нужной ролью. Всё созданное пишется в fixtures.auto.md
(общий для ролей, переиспользуется) и в раздел «Созданные и изменённые сущности» results.md.
В конце команды ненужные QA-AUTO-сущности архивируются/деактивируются. Рекомендуемый порядок:
sysadmin → senior → teamadmin → member. BLOCKED остаётся только для webhook, визуальных проверок
и неустранимых предусловий.
Режим «Посмотреть как» не заменяет проверку прав отдельного пользователя.
FRM-03 и FLC-06 расходятся в условиях удаления — нужно уточнить требование.
ANS-05 требует доказательств из приёмника webhook. Визуальные/временные проверки не доказываются одним DOM-снимком.

## Отчёты и настройки

Каждый прогон создаёт reports/<время>-<кейс|раздел|chat>-<роль>/ с prompt.txt, run.json и results.md.
Агент дополняет results.md и сохраняет доказательства. run.json фиксирует запуск, а не результат тестов.
Если агент завершился без отчёта, начальный NOT_RUN остаётся — это не PASS.
Статусы: PASS, FAIL, BLOCKED, AGENT_ERROR. Не проверенные условия перечисляются отдельно.

Общие параметры в config.json: URL, baseModel, model, context, chromePath. Распределение по ролям — roles.json.
Чтобы изменить модель на обоих Mac, измените config.json и повторите bash start.sh.
Modelfile генерируется из config.json. Модели Ollama хранятся отдельно от этой папки.
MCP закреплён на версии 0.0.85, транзитивные зависимости — в package-lock.json.
Claude Code и приложения устанавливаются в актуальных версиях, их версии на разных Mac могут отличаться.
Модель подключена к localhost:11434. Облачный вариант через Chrome — см. раздел «Облачная модель + расширение Claude in Chrome».

После правок исходного regression.md:

```bash
bash run.sh split
```

Передайте боссу папку с исходниками, включая скрытые .mcp.json и .gitignore,
но без node_modules/, .runtime/, profiles/, chrome-profile/, reports/ и fixtures.local.md.
Внутри нет абсолютных путей к домашнему каталогу автора.
Остановить работу: Ctrl+C. Полный регресс здесь ещё не запускался.

## Команды внутри Claude Code

После установки запустите чат:

```bash
bash run.sh chat
```

Роль при запуске не нужна. Внутри Claude Code:

```text
/regress_sysadmin
/regress_sysadmin TEAM
/regress_sysadmin продолжить с GRID-03 × Команды
```

Одна команда на роль: /regress_sysadmin, /regress_senior, /regress_teamadmin, /regress_member.
Каждая команда сама сбрасывает браузер (browser_close) и входит под секретами своей роли
(QA_<РОЛЬ>_LOGIN/PASSWORD), затем идёт по suites/<роль>.md раздел за разделом.
В одном чате можно запускать роли по очереди: `/regress_member`, потом `/regress_senior` и т.д.
Результаты всех ролей чата пишутся в один results.md с колонкой роли.
Для длинных наборов (sysadmin, senior) из-за контекста модели удобнее отдельный чат на роль.
Без тестовых данных зависимые проверки будут BLOCKED. Команды не запускают вложенный Claude Code.
При переполнении контекста модель сохраняет точку продолжения в results.md; её можно передать
в новом чате: `/regress_senior продолжить с FRM-03, предыдущий отчёт reports/.../results.md`.
Один длинный прогон на 4B-модели не гарантирует завершения без вмешательства.

Файлы команд находятся в .claude/commands/, общие инструкции — .claude/regress-workflow.md.
Они передаются боссу вместе с папкой, включая скрытую .claude/.
После изменения настроек перезапустите чат. Однократное доверие к проекту/MCP может остаться;
корпоративные запреты имеют приоритет над локальными разрешениями. Правило mcp__playwright__*
разрешает все инструменты именно этого сервера, включая действия, меняющие данные сайта.
Запись отчётов файловыми инструментами Claude может запросить отдельное подтверждение.

## Автоматический вход через .env

Откройте локальный .env (создаётся при setup) и заполните нужную роль:

```dotenv
QA_SYSADMIN_LOGIN='test-admin'
QA_SYSADMIN_PASSWORD='ваш пароль'
```

Для других ролей: QA_SENIOR_LOGIN/PASSWORD, QA_TEAMADMIN_LOGIN/PASSWORD,
QA_MEMBER_LOGIN/PASSWORD. Шаблон всех имён находится в .env.example.
Затем перезапустите `bash run.sh chat` и вызовите /regress_<роль>.
В уже открытом чате настройки входа не обновляются.

Каждый запуск и каждый вызов /regress_<роль> начинают с чистого контекста и нового входа. Модель получает только имена
секретов; Playwright MCP подставляет значения из .env при browser_fill_form/browser_type.
Значения не включаются в prompt.txt или аргументы запуска. Файл .env исключён из Git и
запрещён для Read в Claude Code; не добавляйте его в fixtures или отчёты и не передавайте боссу.
Это не абсолютная изоляция секретов от браузерного агента: у него есть доступ к браузеру и другим инструментам.
Автологин разрешён только на origin из config.json; для SSO, MFA, CAPTCHA или ошибки пароля нужен ручной вход.
После одной ошибки агент должен остановиться, чтобы не повторять неверные попытки.
Без заполненной пары секретов launcher останавливается до запуска браузера. Команда login выполняет только новый вход из .env.
При закрытии изолированного браузера cookies и локальное состояние этого контекста теряются. Старые сессии на сервере не отзываются; личный Chrome не затрагивается.
Каждый пользователь заполняет собственный .env. Боссу передаётся только .env.example.

## Что передавать по итогам

Один файл `reports/<папка-прогона>/results.md`: сводка, таблица статусов, описания ошибок
и список непроверенного. В пределах чата все вызовы /regress_<роль> дополняют один results.md (по файлу на роль).
Служебные файлы рядом нужны для диагностики, передавать их вместе с результатами необязательно.
Новый чат создаёт новый файл; автоматического объединения результатов разных чатов нет.

## Облачная модель + расширение Claude in Chrome

Альтернатива Ollama + Playwright: облачный Claude управляет вашим обычным Chrome через расширение
Claude in Chrome. Нужны: вход в Claude Code под аккаунтом claude.ai (`claude` → `/login`),
установленное и включённое расширение, открытый Chrome.

```bash
bash run.sh cloud                 # claude --chrome, отчёт в reports/<время>-chrome/
bash run.sh cloud --model opus    # явно выбрать модель
```

Внутри чата:

```text
/regress-chrome sysadmin
/regress-chrome teamadmin TEAM
/regress-chrome senior продолжить с FRM-03 отчёт reports/.../results.md
```

Скилл лежит в `.claude/skills/regress-chrome/SKILL.md` и работает по тем же suites/, cases/,
правилам данных и формату отчёта. Отличие — вход: пароли из .env облачной модели не передаются,
поэтому под нужной ролью (и для SETUP под сисадмином) вы логинитесь сами в открытой вкладке
и пишете агенту «вошёл». Тестовые учётки удобно хранить в менеджере паролей Chrome.
Агент работает в вашем профиле Chrome: открывает свою вкладку и не трогает чужие.
