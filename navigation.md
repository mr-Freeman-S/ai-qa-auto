# Как открыть плагин «Таблицы»

## Вход: обязательный порядок действий

Перед вводом секретов проверь origin сайта из config.json. После сброса сессии
получи browser_snapshot без filename. Если ответ содержит только ссылку на .yml,
прочитай именно этот файл snapshot инструментом Read, прежде чем выбирать элемент.
Ссылка на snapshot не означает, что страница пустая.

1. Найди поля логина, пароля и кнопку входа в свежем snapshot. Используй targets/refs
   из текущего ответа; не придумывай селекторы по названию кнопки.
2. Заполни поля через browser_fill_form/browser_type буквальными именами секретов
   выбранной роли. Значения подставляет MCP; не читай .env и не выводи содержимое полей.
3. По успешному логу пользователя от 13.11.2026 кнопка «Log in» имеет id saveSetting
   (CSS #saveSetting). #log-in на этой форме не существует. Предпочитай актуальный
   target/ref кнопки «Log in» из snapshot; #saveSetting используй только если текущий
   DOM подтверждает этот id. Не нажимай Show password / #password_toggle.
4. После клика дождись интерфейса Mattermost и нового snapshot. Переход на /channels/
   вместе с основным интерфейсом подтверждает вход; один title «Log in - SECURE»
   не доказывает неудачу — заголовок может обновиться позже.
5. Если target не найден, получи новый snapshot и сделай одну исправленную попытку.
   Это ошибка поиска элемента, а не отказ сервера принять пароль. После второго
   сбоя выбора элемента — AGENT_ERROR; после явного отказа авторизации — BLOCKED,
   повторно пароль не отправляй.

Не диагностируй вход через browser_evaluate/browser_run_code: для этой формы достаточно
snapshot, fill/type и click. Не генерируй JavaScript, не перебирай селекторы, не добавляй
await для свойств DOM. Если snapshot не появился, следуй разделу ожидания загрузки ниже.


Плагин зарегистрирован как продукт Mattermost: switcherText «Таблицы», switcherLinkURL /form-plugin
(источник: webapp/src/index.tsx). Это не канал и не пункт меню профиля.

Проверено живым браузером 12.11.2026:
- Кнопка: accessible name `Product switch menu`, selector `#product_switch_menu`.
- Пункт: selector `#product-menu-item-form-plugin`, текст `Таблицы`.
Сначала ищи эти элементы в свежем snapshot/DOM. Визуальный поиск нужен только если их нет.
После открытия /form-plugin дождись полной загрузки: вкладки Каналы/Поля могут появиться позже первых пяти.

1. После входа дождись основного интерфейса Mattermost.
2. Закрой меню профиля/другие всплывающие окна клавишей Escape, если они открыты.
3. Найди переключатель приложений в САМОМ ВЕРХНЕМ ЛЕВОМ углу: иконка сетки 3×3
   (девять квадратов), слева от названия сервера. Не путай её с аватаром справа сверху, шестерёнкой,
   списком команд слева или меню текущего канала.
4. Получи свежий browser_snapshot. Найди соответствующий элемент по доступному имени,
   атрибутам или DOM. Если имя отсутствует, изучи DOM кнопок верхней панели через
   browser_evaluate без чтения значений полей и секретов. Не выдумывай selector/ref
   и не используй координаты или refs из прошлых прогонов.
5. Открой переключатель и получи новый snapshot. Для DISP-01 проверь именно пункты
   открытого меню согласно роли: Channels / Таблицы / System Console.
   Сохрани доказательство открытого меню. Заголовок CHANNELS над списком каналов
   не заменяет пункт Channels в переключателе приложений.
6. Для входа в плагин нажми «Таблицы» в этом меню. Дождись страницы /form-plugin
   (возможен вложенный путь) и навигации плагина. Затем выполняй DISP-02 и другие кейсы.
   Для мембера отсутствие «Таблицы» ожидаемо: не пытайся открыть пункт, которого нет.

Для кейсов, где проверяется содержимое плагина, а не вход через меню, допускается
прямой переход на URL сайта из config.json + /form-plugin. Не угадывай /plugins/form-plugin.
Прямой переход не доказывает PASS для DISP-01 и не скрывает неисправность переключателя.
Если после двух попыток не удалось определить кнопку — опиши наблюдения из snapshot в results.md,
отметь AGENT_ERROR, а не FAIL продукта. Если меню открыто и ожидаемого пункта действительно
нет при подтверждённой роли — зафиксируй наблюдаемое расхождение отдельно.

## Заголовок SECURE и пустой snapshot

На этом staging HTML по /form-plugin имеет <title>SECURE</title>, содержит root,
initialPageLoadingScreen и JavaScript приложения. Сам заголовок SECURE не является
ошибкой, экраном запрета или доказательством отдельной авторизации плагина.
Плагин использует авторизованную сессию Mattermost (server/internal/api/middleware/access.go).

После перехода сначала проверь фактический URL, дождись загрузки интерфейса и получи
свежий snapshot. Если он пустой, сделай до трёх ожиданий по 5 секунд с новым snapshot.
Это ожидание загрузки, а не повторение кликов. Если контент не появился, запиши это в results.md,
проверь browser_console_messages и browser_network_requests на ошибки загрузки JS/API.
Не сохраняй тела запросов, cookies, заголовки авторизации или пароли.
В отчёте укажи наблюдаемую ошибку и URL без чувствительных параметров.
Пустой snapshot без дополнительных доказательств не доказывает отсутствие кнопки или запрет роли:
пометь диагностику как AGENT_ERROR, а зависимые кейсы — BLOCKED.
Не предлагай отдельный логин в плагин и смену роли лишь на основании title SECURE.
Если видна настоящая форма входа Mattermost, используй настроенный автологин.
