# Итоговый файл результатов

Пользователь получает один самодостаточный файл results.md в папке текущего прогона,
указанной в стартовом задании. Записывай результаты после каждого кейса прямо в этот файл.
Не создавай отдельные report.md или progress.md. В одной сессии вызовы /regress_<роль> дополняют
общий results.md; при повторной проверке добавляй новую попытку с временем, сохраняя историю.
Для сводки учитывай последнюю попытку каждой пары ID + роль + таблица.

## Как физически сохранить отчёт

Текст в ответе чата НЕ записывает файл. Используй файловые инструменты Claude Code:
1. Read: прочитай results.md по точному пути из стартового задания.
2. Write: запиши полный Markdown с сохранением прежних результатов, добавив текущий кейс.
   Для точечной правки допустим Edit. Не записывай отчёт через browser_evaluate/run_code:
   они работают в браузере, а не являются файловыми инструментами Claude Code.
3. Read: заново прочитай этот же results.md. Проверь, что в нём есть добавленный ID,
   статус и фактический результат. Только успешное чтение подтверждает сохранение.
4. Если запись недоступна или чтение не подтвердило результат, сообщи «Не удалось
   сохранить отчёт» и выведи накопленный Markdown в чат. Не говори «Отчёт обновлён».

После каждого кейса выполняй запись и проверку; не откладывай их до конца раздела.
Стартовая строка NOT_RUN не является результатом проверки.

Формат файла:

# Результаты регресса

- Сайт, дата и время (Europe/Minsk), модель, роль.
- Область проверки: набор роли (suites/<роль>.md), разделы и таблицы.
- Состояние прогона: IN_PROGRESS / COMPLETED / INTERRUPTED / NOT_RUN.
- Сводка: количество PASS / FAIL / BLOCKED / AGENT_ERROR / SKIPPED / NOT_RUN.

| Кейс | Проверка | Роль / таблица | Статус | Фактический результат |
| --- | --- | --- | --- | --- |

## Созданные и изменённые сущности

Тип, имя (QA-AUTO…), ID, что сделано (создано/изменено/архивировано/оставлено для другой роли), кейс.
Чужие данные стенда не изменяются; SETUP-шаги под сисадмином отмечай отдельно.

## Ошибки и незавершённые проверки

Для каждого FAIL: ID, шаги воспроизведения, ожидаемо, фактически.
Для BLOCKED/AGENT_ERROR/SKIPPED: причина и что необходимо для проверки.
Укажи непроверенные условия; частичная проверка не является PASS всего кейса.
Текст должен быть понятен без открытия скриншотов и логов.
По умолчанию не вызывай browser_take_screenshot и не сохраняй изображения.
Используй snapshot/DOM и описывай наблюдения текстом в results.md.
Если проверка требует изображения и без него недостоверна, отметь её BLOCKED
с причиной «нужна визуальная проверка»; не объявляй PASS по одному DOM.
Скриншоты создавай только по явному запросу пользователя.
Пароли, токены, cookies и содержимое .env в файл не включай.

## Продолжение

Оставшиеся разделы/строки набора и точка продолжения (ID × таблица), если прогон не завершён.
COMPLETED означает, что выбранный набор обработан, а не что все кейсы прошли.
Отчёт агента требует проверки человеком.

В финальном ответе пользователю достаточно пути/ссылки на results.md и короткой сводки.
Перед ответом прочитай сохранённый файл и проверь соответствие сводки строкам таблицы.

Не выдавай предположения за причины сбоя: отделяй наблюдаемый факт от гипотезы.
Заголовок страницы SECURE и пустой snapshot сами по себе не доказывают отказ доступа.
Для проблем навигации применяй диагностику из navigation.md.
