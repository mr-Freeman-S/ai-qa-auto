# Регресс через Claude in Chrome (облачная модель)

Аргументы: `$ARGUMENTS`

Этот скилл заменяет Playwright MCP + локальную Ollama на расширение Claude in Chrome
в обычном Chrome пользователя и облачную модель Claude. Наборы, кейсы, правила данных
и формат отчёта — те же, что у /regress_<роль>.

## 0. Разбор аргументов

- Первое слово — роль: `sysadmin`, `senior`, `teamadmin`, `member`
  (принимай и русские: сисадмин, старший, тимадмин, мембер). Нет роли — спроси и остановись.
- Дальше необязательно: раздел (`TEAM`), ID (`USR-06`, `GRID-03 × Команды`),
  `продолжить с <ID>`, путь к прошлому `results.md` (тогда дописывай в него).

## 1. Подготовка

1. Прочитай `config.json` (url), `.claude/regress-workflow.md`, `report-format.md`,
   `suites/<роль>.md`. `navigation.md` — только разделы про плагин (переключатель приложений,
   SECURE, ожидание загрузки); раздел про вход через секреты Playwright здесь НЕ применяется.
   Не читай regression.md целиком и все cases/ сразу — по одному `cases/<ID>.md` на строку набора.
2. Папка отчёта: `$QA_REPORT_DIR`, если задан (запуск через `bash run.sh cloud`), иначе
   переданный путь к results.md, иначе создай `reports/<YYYY-MM-DDTHH-MM>-chrome-<роль>/`.
   Создай `results.md` по report-format.md, модель указывай как «Claude (облако) + Claude in Chrome».
3. Загрузи инструменты расширения одним вызовом ToolSearch:
   `select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__tabs_create_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__read_page,mcp__claude-in-chrome__find,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__form_input,mcp__claude-in-chrome__get_page_text,mcp__claude-in-chrome__javascript_tool,mcp__claude-in-chrome__read_console_messages,mcp__claude-in-chrome__read_network_requests`
   Если расширение не отвечает — скажи пользователю проверить, что Chrome открыт,
   расширение Claude включено и сессия запущена с `--chrome` (или `/chrome`), и остановись.
4. `tabs_context_mcp`, затем создай НОВУЮ вкладку (`tabs_create_mcp`) и открой url из config.json.
   Чужие вкладки пользователя не трогай и не закрывай.

## 2. Вход под ролью — вручную пользователем

Секреты из .env модели не передаются: облачная модель не должна видеть пароли,
а `.env` запрещён для Read. Поэтому:

1. Открой сайт и определи, кто сейчас залогинен (аватар/меню профиля, `/api/v4/users/me`
   через navigate — только username и роли, без токенов).
2. Если вход не под учёткой нужной роли — попроси пользователя: «Войдите в этой вкладке
   под тестовой учёткой роли <роль> (можно через менеджер паролей Chrome) и напишите
   „вошёл“». Жди ответа, сам логин/пароль не вводи и не спрашивай.
3. После «вошёл» подтверди фактическую роль. «Посмотреть как» роль не заменяет.
4. SETUP под сисадмином (п.5d workflow): так же попроси пользователя перелогиниться
   на сисадмина, сделай SETUP, затем попроси вернуться в роль команды. Группируй SETUP-шаги,
   чтобы переключений было как можно меньше.

## 3. Прогон

Иди по `suites/<роль>.md` раздел за разделом (или только заданный раздел / с точки продолжения).
Для каждой строки:

1. Прочитай `cases/<ID>.md`, проверяй ветку ожиданий своей роли («Фокус роли» в наборе).
2. Действуй через расширение: `read_page`/`find` для поиска элементов, `computer` для кликов
   и ввода, `navigate` для прямых ссылок (проверки запрета доступа), `form_input` для полей.
   `javascript_tool` — только для чтения DOM, не для обхода UI и не для чтения cookies/токенов.
   Не вызывай действия, открывающие alert/confirm браузера, без предупреждения (они вешают расширение).
3. Правила данных — п.5 workflow без изменений: создаёшь сам с префиксом `QA-AUTO <ММДД-ЧЧММ>`,
   email `@example.invalid`, меняешь только QA-AUTO и то, что в fixtures.local.md; учёт в fixtures.auto.md,
   уборка в конце.
4. Статусы и критерии — п.4, п.6, п.7 workflow (PASS только при всех условиях, GRID-строка = одна таблица,
   две одинаковые неудачи → AGENT_ERROR, FRM-03/FLC-06 — обе трактовки).
5. После КАЖДОГО кейса: Edit/Write `results.md`, затем Read и проверь, что строка с ID,
   статусом и фактом на месте.
6. Не застревай: 2–3 неудачные попытки с элементом → AGENT_ERROR и следующий кейс.
   Расширение перестало отвечать / сайт недоступен → сохрани точку продолжения и остановись.

Скриншоты в отчёт не сохраняй без просьбы — доказательства описывай текстом
(URL, видимые тексты, наличие/отсутствие элементов). Для визуальных проверок можно
смотреть скриншот `computer` и описать увиденное.

## 4. Финиш

Сводка по статусам в results.md (состояние COMPLETED/INTERRUPTED), уборка QA-AUTO,
в чат — числа статусов, путь к отчёту и как продолжить:
`/regress-chrome <роль> продолжить с <ID> отчёт <путь>/results.md`.
Вкладку оставь открытой.

Не применяются из workflow: browser_close, вход через секреты Playwright, ограничения
«контекст 4B-модели», запрет на JavaScript при входе (вход делает человек).
